平常在 Angular 中，我們可以透過 `providers` 決定 Service 的注入範圍。例如註冊在 Root，讓整個 Application 共用同一個實例；或註冊在 Component，讓 Service 隨著 Component 一起建立與銷毀。

除了這兩種方式，Angular Router 也允許我們在 Route 中宣告 `providers`，讓特定路由及其子路由使用專屬的 Service。

不過，這裡有個容易忽略的問題：**當使用者離開路由時，註冊在 Route Providers 的 Service，也會跟著銷毀嗎？**

今天就透過一個簡單的範例觀察這個行為，再介紹 Angular 22.2 正式提供的 `withAutoCleanupInjectors()`。

## Route Providers 的生命週期

首先建立一個 `CounterService`，透過 `OnDestroy` 觀察 Service 什麼時候被銷毀。

`counter/counter.service.ts`

```ts
import { Injectable, OnDestroy } from '@angular/core';

let nextId = 0;

@Injectable()
export class CounterService implements OnDestroy {
  readonly id = ++nextId;

  constructor() {
    console.log(`CounterService #${this.id} created`);
  }

  ngOnDestroy() {
    console.log(`CounterService #${this.id} destroyed`);
  }
}
```

這裡用 `nextId` 記錄 Service 建立的次數，每次建立新實例時，`id` 就會增加 1。即使 Service 被銷毀，`nextId` 也不會重設，方便區分不同的實例。

接著建立 Counter 頁面，注入剛才的 Service，並使用 `input()` 接收路由參數。

`counter/counter.component.ts`

```ts
import { Component, inject, input, OnDestroy } from '@angular/core';
import { CounterService } from './counter.service';

@Component({
  selector: 'app-counter',
  templateUrl: './counter.component.html',
  styleUrl: './counter.component.css',
})
export class CounterComponent implements OnDestroy {
  readonly id = input<string>();
  readonly counterService = inject(CounterService);

  constructor() {
    console.log('CounterComponent created');
  }

  ngOnDestroy() {
    console.log('CounterComponent destroyed');
  }
}
```

`counter/counter.component.html`

```html
<h2>Counter 頁面</h2>

<p>Route ID：{{ id() }}</p>
<p>Service ID：{{ counterService.id }}</p>
```

畫面會顯示路由參數與 Service ID，方便觀察兩者是否會隨著路由切換而重新建立。

### 設定 Route Providers

接著設定首頁與 Counter 頁面兩個路由。

`app.routes.ts`

```ts
import { Routes } from '@angular/router';
import { CounterService } from './counter/counter.service';

export const routes: Routes = [
  {
    path: '',
    loadComponent: () =>
      import('./home.component').then(m => m.HomeComponent),
  },
  {
    path: 'counter/:id',
    loadComponent: () =>
      import('./counter/counter.component').then(
        m => m.CounterComponent
      ),
    providers: [CounterService],
  },
];
```

這裡將 `CounterService` 註冊在 `counter/:id` 路由的 `providers`，而不是 Root 或 Component。

Angular 的 DI 主要分成兩種 Injector 階層：

- **`EnvironmentInjector`**：管理特定環境的依賴，包含 Root Injector 與 Route Injector。
    - **Root Injector**：管理 Application 層級的 Service，通常透過 `providedIn: 'root'` 註冊。
    - **Route Injector**：管理特定路由及其子路由的 Service，透過 Route `providers` 註冊。
- **`ElementInjector`**：管理 Component 與 Directive 的依賴，例如透過 Component 的 `providers` 註冊 Service。

這次使用的 Route Providers 屬於 `EnvironmentInjector` 階層。當 Router 需要這個路由提供的依賴時，就會建立對應的 Injector，管理其中的 Service。

接著在 `app.html` 加入導覽連結：

```html
<nav>
  <a routerLink="/">首頁</a>
  |
  <a routerLink="/counter/1">Counter 1</a>
  |
  <a routerLink="/counter/2">Counter 2</a>
</nav>

<router-outlet />
```

`app.ts` 則引入 `RouterLink` 與 `RouterOutlet`：

```ts
import { Component } from '@angular/core';
import { RouterLink, RouterOutlet } from '@angular/router';

@Component({
  selector: 'app-root',
  imports: [RouterLink, RouterOutlet],
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {}
```

首頁只需要簡單的內容，方便切換路由。

`home.component.ts`

```ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-home',
  template: `<h2>首頁</h2>`,
})
export class HomeComponent {}
```

設定 Router，先不加入自動清理功能。

`app.config.ts`

```ts
import {
  ApplicationConfig,
  provideBrowserGlobalErrorListeners,
} from '@angular/core';

import {
  provideRouter,
  withComponentInputBinding,
} from '@angular/router';

import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideRouter(
      routes,
      withComponentInputBinding()
    ),
  ],
};
```

這裡使用 `withComponentInputBinding()`，讓 Router 自動將 `:id` 綁定到 Component 的 `id` Input，不需要另外透過 `ActivatedRoute` 監聽參數。

### 觀察執行結果

現在打開瀏覽器的 Console，從首頁切換到 Counter 1。

第一次進入時，會看到：

```text
CounterService #1 created
CounterComponent created
```

畫面顯示：

```text
Route ID：1
Service ID：1
```

接著切換到 Counter 2：

```text
Route ID：2
Service ID：1
```

這時不會有新的 `created` 或 `destroyed` 訊息，因為兩個網址使用相同的 Route Configuration，Angular 預設會重用 Component 與 Service。

再返回首頁：

```text
CounterComponent destroyed
```

這時會發現，**Component 已經銷毀，但 `CounterService` 並沒有執行 `ngOnDestroy()`。**

如果再次進入 Counter 1，畫面仍然顯示 `Service ID：1`，也不會再次輸出 `CounterService created`。

這是因為 Route Providers 所建立的 `EnvironmentInjector`，預設不會因為離開路由就立即銷毀。當再次進入相同的 Route Configuration 時，仍然會使用原本的 Service 實例。

因此，**Component 與 Route Provider 有各自的生命週期，即使 Component 已經銷毀，Service 仍然可能存在。**

![Angular Route Provider 生命週期比較](https://res.cloudinary.com/dseg0uwc9/image/upload/v1791987629/2026%20%E9%90%B5%E4%BA%BA%E8%B3%BD/Day%2030%EF%BC%9AAngular%20Router%20Providers%20%E8%88%87%E7%94%9F%E5%91%BD%E9%80%B1%E6%9C%9F%E7%AE%A1%E7%90%86%EF%BC%8C%E8%B7%AF%E7%94%B1%E9%9B%A2%E9%96%8B%E5%BE%8C%20Service%20%E6%9C%83%E9%8A%B7%E6%AF%80%E5%97%8E%EF%BC%9F/Angular%20Route%20Provider%20%E7%94%9F%E5%91%BD%E9%80%B1%E6%9C%9F%E6%AF%94%E8%BC%83.png)

## withAutoCleanupInjectors()

如果希望離開路由後，能自動清理不再使用的 Route Injector，Angular Router 提供了 `withAutoCleanupInjectors()`。

這個功能在 Angular 22.2 成為 Stable API，只需要在 `provideRouter()` 加入設定即可。

`app.config.ts`

```ts
import {
  ApplicationConfig,
  provideBrowserGlobalErrorListeners,
} from '@angular/core';

import {
  provideRouter,
  withComponentInputBinding,
  withAutoCleanupInjectors,
} from '@angular/router';

import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideRouter(
      routes,
      withComponentInputBinding(),
      withAutoCleanupInjectors(),
    ),
  ],
};
```

原本的 Route、Component 和 Service 都不用修改。

### 再次觀察執行結果

重新整理頁面，再從首頁進入 Counter 1。

```text
CounterService #1 created
CounterComponent created
```

接著切換到 Counter 2，畫面上的 Route ID 會變成 `2`，但 Service ID 仍然是 `1`，Component 和 Service 都沒有重新建立。

這次返回首頁時，Console 會顯示：

```text
CounterComponent destroyed
CounterService #1 destroyed
```

除了 Component，`CounterService` 的 `ngOnDestroy()` 也執行了。

如果再次進入 Counter 1：

```text
CounterService #2 created
CounterComponent created
```

畫面上的 Service ID 也會變成 `2`，表示 Router 重新建立了 Injector 與 Service 實例。

比較兩種設定的差異：

| 行為 | 預設設定 | 啟用自動清理 |
| --- | --- | --- |
| 離開路由時銷毀 Component | 是 | 是 |
| 清理不再使用的 Route Injector | 不會自動清理 | 會自動清理 |
| 再次進入相同路由 | 重用原本的 Service | 建立新的 Service |
| Service `ngOnDestroy()` | 不會因離開路由而觸發 | Injector 銷毀時觸發 |

不過，`withAutoCleanupInjectors()` 並不是每次切換路由都會銷毀所有 Service。Router 會在導航完成後，檢查哪些 Route Injector 已經不再使用，再配合 `RouteReuseStrategy` 決定是否清理。

![Angular Router Providers 生命週期：預設設定與自動清理的差異](https://res.cloudinary.com/dseg0uwc9/image/upload/v1791960049/2026%20%E9%90%B5%E4%BA%BA%E8%B3%BD/Day%2030%EF%BC%9AAngular%20Router%20Providers%20%E8%88%87%E7%94%9F%E5%91%BD%E9%80%B1%E6%9C%9F%E7%AE%A1%E7%90%86%EF%BC%8C%E8%B7%AF%E7%94%B1%E9%9B%A2%E9%96%8B%E5%BE%8C%20Service%20%E6%9C%83%E9%8A%B7%E6%AF%80%E5%97%8E%EF%BC%9F/router-providers-lifecycle-v2.png)

## RouteReuseStrategy 與 Injector 清理

在 Day 23 已經介紹過 `RouteReuseStrategy` 的基本用法，這裡補充它與 `withAutoCleanupInjectors()` 的關係。

當 Router 啟用自動清理後，除了目前正在使用的路由，也要考慮被 `RouteReuseStrategy` 保存的路由。如果 Component 只是暫時被 detach，對應的 Injector 也需要保留，否則之後重新 attach 時可能發生問題。

為了配合這個機制，`RouteReuseStrategy` 另外提供兩個方法：

- **`shouldDestroyInjector()`**：決定 Route Injector 是否允許被銷毀。
- **`retrieveStoredRouteHandles()`**：回傳目前保存的 `DetachedRouteHandle`，讓 Router 知道哪些路由仍然需要保留。

如果使用預設的 `RouteReuseStrategy`，或繼承 `BaseRouteReuseStrategy`，`shouldDestroyInjector()` 已經有預設行為。如果自訂策略會保存 `DetachedRouteHandle`，則需要透過 `retrieveStoredRouteHandles()` 提供目前保存的內容，避免對應的 Injector 被提前清理。

前面的 Counter 範例也能看到，即使啟用了 `withAutoCleanupInjectors()`，從 `/counter/1` 切換到 `/counter/2` 時，Component 與 Service 仍然會被重用。

這是因為兩個網址使用相同的 Route Configuration，Angular 會直接沿用目前的 Component，不需要透過 detach / attach 保存與還原頁面。由於 Route Injector 仍然在使用中，因此也不會被自動清理。

## Route Provider 與 Root Provider 的清理範圍

`withAutoCleanupInjectors()` 只會清理不再使用的 Route Injector，不會影響 Root Injector。

例如，前面的 `CounterService` 沒有設定 `providedIn: 'root'`，而是透過 Route Providers 註冊：

```ts
{
  path: 'counter/:id',
  providers: [CounterService],
}
```

當 Route Injector 被銷毀時，`CounterService` 也會跟著銷毀。

但如果改成在 Root 註冊：

```ts
@Injectable({
  providedIn: 'root',
})
export class CounterService {}
```

而且沒有在 Route Providers 另外註冊，就會使用 Root Injector 提供的實例。即使離開 Counter 頁面，Service 也不會因此被銷毀。

如果兩邊都有註冊，Angular 會優先使用 Route Providers 提供的實例，而 Root 的實例仍由 Root Injector 管理，兩者有各自的生命週期。
